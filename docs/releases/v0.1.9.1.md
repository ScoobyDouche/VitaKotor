## The area-transition crash is fixed

Every session before this one ended the same way: 10-20 minutes in, you'd walk
through a door and the game would freeze. That's gone. The longest test run for
this release went **44 minutes across several area loads** with the game's heap
still healthy at the end.

The cause was fragmentation, not exhaustion. The game mixes megabyte-sized
allocations in with thousands of small long-lived objects, and over a session
that shreds the heap into confetti. There was plenty of memory free, just never
enough of it in one contiguous piece to satisfy a routine 1 MB request. Large
allocations now come from a pool of their own, away from the small-object churn.

## You can name your character

Character creation couldn't be finished. Tapping the name box is supposed to
bring up a keyboard: on Android the system provides one, but on Vita nothing
did, so you could never type a single letter. The game won't accept a blank
name, so that was the end of the road. It now brings up the Vita's own
on-screen keyboard, and the same fix covers naming your saves.

## Audio no longer dies over a long session

Sound would thin out and then disappear entirely, voices included, eventually
taking the game with it. The engine was never being told when a sound finished,
so it never reused a voice or closed a music stream, and the leak ran both file
handles and memory dry.

## Known issue: the picture can degrade in a long session

After roughly 40 minutes the world geometry can start tearing into diagonal
streaks, getting worse over the following minute or two, while the HUD and
dialogue text keep drawing perfectly. It isn't tied to any particular area. It
builds with time played and follows you when you walk elsewhere.

**Nothing crashes and your save is safe.** Relaunching and loading the same save
came back clean. This has been seen once; a later 52-minute session showed no
sign of it, so it is real but not reliable.

What's known so far: it is not a failed allocation (vitaGL reports none) and the
game's own heap is healthy at the time.

## Also in this release

- Controls are now documented in the README, including the Vita button index
  table for anyone building on this
- Heap and video-memory telemetry in `log.txt`, which is what made the crash
  diagnosable in the first place
- 4x MSAA is off by default, and redundant texture binds are skipped

## Installing

You need your own copy of the **Android** release of KOTOR: the `.apk` and both
`.obb` files. Nothing here contains game code or data. See the README for the
full setup, including `kubridge.skprx` and `libshacccg.suprx`, both of which are
required.

Save often. It's worth playing in sessions now; it's not yet a playthrough.
