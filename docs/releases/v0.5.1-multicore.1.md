# VitaKotor v0.5.1-multicore.1 — the AI gets its own core

A test pre-release from the `multicore` branch. The game's AI now runs on a second CPU core while the 3D scene draws, instead of after it. It has had two short test sessions, so it is a pre-release for anyone who wants to try it early.

## What changed

- **The AI runs alongside the graphics.** Every frame the game used to draw the scene, then run the AI for every creature in the area, one after the other on the same core. The AI now starts on another core as the scene starts drawing, so the two overlap. In busy areas that takes about 3.5 ms off each frame, on top of v0.5.0's graphics core.

- **It can be switched off.** Add `ServerOverlap=0` under `[Vita Options]` in `ux0:data/kotor/swkotor.ini` to go back to the old order without reinstalling.

- **Two sound fixes**: a race in the mixer could make a replayed track carry on from where it last stopped, and a released stream could be closed while it was still being decoded. Both found in VitaKotor2.

- **A graphics fix**: a deleted buffer stayed bound, so a later draw could read freed memory. It is now unbound first, as OpenGL requires.

- **KOTOR-nolog.vpk**: an optional build with diagnostic logging disabled. Install it in place of `KOTOR.vpk` if you prefer not to have a log file written.

### How it stays safe

The AI sometimes reaches straight into the things being drawn: it moves models, starts animations and loads scripts. Around 1,350 of the game's drawing and resource functions are guarded, and if the AI reaches one while the scene is drawing, it waits until the drawing is done and then carries on. Area changes, saves, loads and quitting all finish the AI's frame first. A few functions that only store a position or look up a resource are let through, after checking what they do.

### Why only 3.5 ms

The AI is about 5.5 ms of a busy frame, and in two thirds of frames it still has to wait at one of the guards before it finishes. The 3D scene itself, about 30 ms, is the game's own code on one core and is unchanged.

## Updating

Install `KOTOR.vpk` over your current one. Your files in `ux0:data/kotor/`, your saves and your mods stay as they are. If anything goes wrong, set `ServerOverlap=0`, or reinstall v0.5.0 from the releases page.

## Honest limits

- **Tested for two short sessions, not a playthrough.** Busy areas with full graphics settings on, with no crashes and nothing wrong on screen.

- **The AI reacts one frame later**, about 33 ms. It has not been noticeable in play.

- **Mod sets have not been tried with this build.**

- **The loading screen runs twice when you load a save** (issue #13), and **the rare crash after an area-change auto-save** (issue #12) is still open.

## Everything else from v0.5.0 still applies

The graphics calls run on their own core, setup mistakes show a message, the 1.0.10, 1.0.9 build 54 and 1.0.7 / 1.0.71 APKs work, and frames are locked to 30 fps.

## You need your own copy of the game

This is a loader, not a game. It needs the Android release's `main` and `patch` `.obb` files, which you must own.

## Something broken?

Open an issue with `ux0:data/kotor/log.txt` attached, say where in the game it happened, and whether it still happens with `ServerOverlap=0`.
