# VitaKotor v0.5.2 — two more cores at work

Everything from the v0.5.0 and v0.5.1-multicore pre-releases, played further and released properly, plus the Google Play 1.0.43 APK and fixes for the d-pad, the boot screen and short stalls in play. If you are coming from v0.4.3, this is everything since.

## What changed

- **The graphics calls run on a second core.** The core running the game no longer does the graphics library's work for every object it draws. Busy frames take about a tenth less time.

- **The AI runs on a third core while the scene draws.** It used to run after the drawing, on the same core. In busy areas that takes about 3.5 ms more off each frame. Add `ServerOverlap=0` under `[Vita Options]` in `ux0:data/kotor/swkotor.ini` to turn it off.

- **The Google Play 1.0.43 APK works** (issue #14), with its 32-bit libraries. A 64-bit phone downloads only the 64-bit ones; the README says how to get the right files. The 1.0.10, 1.0.9 build 54 and 1.0.7 / 1.0.71 APKs still work.

- **A d-pad tap no longer moves a menu selection twice** (issue #15).

- **The boot screen no longer looks frozen.** The loading bar used to stop about 4 seconds in and sit still for 20 more. It now keeps moving until the game is about to show the menu.

- **Fewer short stalls in play**: a hitch about once a second caused by the log writer, sound dropouts during area-change saves, pauses when an area's ambient sounds start on a return visit, and pauses as dialogue lines appear.

- **Shiny materials** (issue #11): two fixes for armour and weapons showing neon colours or another surface's reflection.

- **Sound fixes**: a replayed track could carry on from where it last stopped, a stream could be closed while it was still being decoded, and short sound loops are now kept decoded instead of being decoded again every time they restart.

- **Graphics fixes**: 16-bit textures could come out corrupted, a deleted buffer stayed bound, and one texture update every frame made the game wait for the graphics core.

- **Setup mistakes show a message instead of a black screen.** A missing `kubridge`, `libshacccg`, `.so` file or `.obb` now says what is missing and where it goes.

- **New options** under `[Vita Options]`: `ShadowDistance` (how far creatures cast shadows, default `35`), `ServerOverlap` (above), and `FrameLock=60` now also lifts the game's own 40 fps cap. The README has the full table.

- **KOTOR-nolog.vpk**: an optional build with diagnostic logging disabled. Install it in place of `KOTOR.vpk` if you prefer not to have a log file written.

### The pre-releases

v0.5.0, v0.5.1-multicore.1 and v0.5.1-multicore.2 have been taken down from the releases page: everything in them is in this release.

## Updating

Install `KOTOR.vpk` over your current one. Your files in `ux0:data/kotor/`, your saves and your mods stay as they are. If anything goes wrong, set `ServerOverlap=0`, or reinstall v0.4.3 from the releases page.

## Honest limits

- **Loading a save can occasionally take about 15 seconds longer.** It was seen in 3 of about 10 loads of one large save: one long pause just after the loading screen appears, then the load finishes normally. The cause is being traced.

- **Busy areas still sit near 20 fps.** The Upper City and the Undercity crowds are the game's own code on one core.

- **1.0.43 has had several sessions, not a full playthrough.**

- **Mod sets have not been tried with this build.**

- **The equipment menu issue** (issue #10) is still open.

## Everything else from v0.4.3 still applies

Griff spawns in the Sand People Enclave, texture quality is picked from the MODS button, busy areas have 96 sound channels, and frames are locked to 30 fps.

## You need your own copy of the game

This is a loader, not a game. It needs the Android release's `main` and `patch` `.obb` files, which you must own.

## Something broken?

Open an issue with `ux0:data/kotor/log.txt` attached, say where in the game it happened, and whether it still happens with `ServerOverlap=0`.
