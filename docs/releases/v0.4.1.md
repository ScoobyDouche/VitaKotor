# VitaKotor v0.4.1 — the game thread gets a core to itself

A maintenance release. Nothing new to see; the aim is steadier frames.

## What changed

- **The game's own thread now has CPU core 0 to itself.** KOTOR runs its whole game loop and all its drawing on one thread, which can't be split. That thread is what limits the frame rate, so everything else now runs on the Vita's other two cores. That includes the game's background workers (area loading among them), the sound mixer, the sound loader, the log writer and vitaGL's memory clean-up. Before, any of them could land on the same core as the game and take time from it.

- **The sound mixer outranks the game's background workers.** It now shares a core with some of them and sleeps nearly all the time, so it costs them almost nothing. In return a busy loading thread can't make the sound crackle.

- **The log reports how busy each core is.** Every 12 seconds `log.txt` gets `[cpu]` lines naming each busy thread, its core and its share of that core, plus a total per core. If you report a slowdown, attach the log.

## Updating

Install `KOTOR.vpk` over your current one. Your files in `ux0:data/kotor/`, your saves and your mods stay as they are. The shaders haven't changed, so the shader cache stays valid.

## Honest limits

- **The game thread is still the bottleneck.** Its loop is inside Aspyr's binary and can't be moved onto several cores. This release takes everything else off its core; it can't make that core faster. Busy areas may still drop to around 20 fps.

- Clocks were already at the maximum (444/222/222/166 MHz) and the shader cache was already on, so neither changes here.

## You need your own copy of the game

This is a loader, not a game. It needs the Android release's `main` and `patch` `.obb` files, which you must own.
