# VitaKotor v0.4.1 — a steady 30 fps

A performance release. The frame rate is now locked to 30 fps, so motion is even instead of juddering, and the in-game menus stop freezing.

## What changed

- **Frames are locked to 30 fps.** Before, a frame stayed on screen for two refreshes, then three, then two, so motion juddered even at 30+ fps. Now every frame is shown for the same time. On Dantooine, slow frames went from about 15 per 120 frames to fewer than 1.

- **Grass no longer sways.** Wind made the CPU move every blade of grass each frame. The grass is still drawn; it just stands still. `GrassWind=1` brings the wind back.

- **The game's own thread has a CPU core to itself.** Everything else (sound, loading, the log, vitaGL's memory clean-up) now runs on the Vita's other two cores.

- **The equipment screen no longer freezes for a second.** Opening it made the game rewrite `swkotor.ini` on the card 54 times with the same values. Writes that change nothing are now skipped.

- **Inventory and equipment are quicker.** Recent reads from the game's archives are kept in RAM, so hovering over items doesn't re-read the same textures from the card. Files the game looks for and never finds are remembered instead of searched for again.

- **Your character no longer walks off by itself after closing a menu.** Opening a menu while running could leave the last stick position stuck.

- **Lifting one finger no longer makes the touch cursor jump** when two fingers were on the screen.

- **A damaged archive index is rebuilt** instead of being read.

- **Less logging overhead.** About 25 diagnostic hooks for bugs fixed long ago are gone.

- **KOTOR-nolog.vpk**: an optional build with diagnostic logging disabled. Install it in place of `KOTOR.vpk` if you prefer not to have a log file written.

## Recommended graphics settings

For a steady frame rate, leave **Grass**, **Shadows** and **Frame Buffer** off in the game's graphics options. On Dantooine, with them off it holds 30 fps; with them on it drops to about 18 fps. High quality is fine to leave on.

## New settings

The port now reads these from a `[Vita Options]` section at the end of `ux0:data/kotor/swkotor.ini`:

- `FrameLock=30`: the frame rate cap. `20` for a lower, steadier cap; `0` for the old unlocked behaviour.

- `GrassWind=0`: `1` makes the grass sway again.

- `DrawDistance=0`: caps how far you can see, in metres, in areas with fog. Off by default; it made no measurable difference on Dantooine.

- `ObbCacheKB=8192`: RAM kept for recent archive reads. `0` turns it off.

## Updating

Install `KOTOR.vpk` over your current one. Your files in `ux0:data/kotor/`, your saves and your mods stay as they are.

## Honest limits

- **30 fps is a cap, not a promise.** Busy places, such as Taris's Upper City and Undercity with a crowd, or the Dantooine ruins, still drop to around 20 fps. The game draws on a single CPU core inside Aspyr's own code, and that core is the limit.

- **Grass, Shadows and Frame Buffer cost about 10 fps** together, and grass also stutters while you walk because the game rebuilds it around you.

- **Opening the equipment screen still takes about a fifth of a second** while the game builds the character preview.

- Sith armour can still turn a bright solid colour.

## Everything else from v0.4.0 still applies

Mods load from the memory card, the MODS button switches between mod sets, and sound holds up over long sessions.

## You need your own copy of the game

This is a loader, not a game. It needs the Android release's `main` and `patch` `.obb` files, which you must own.

## Something broken?

Open an issue with `ux0:data/kotor/log.txt` attached, and say where in the game it happened.
