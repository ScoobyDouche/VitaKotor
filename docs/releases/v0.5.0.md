# VitaKotor v0.5.0 — a second core for the graphics

A pre-release. The game's graphics calls now run on their own CPU core, which makes busy scenes faster and smoother. It has had one evening of testing, so it is marked pre-release until more people have played on it.

## What changed

- **The graphics calls run on a second core.** Until now the core running the game also did all of vitaGL's work for every object it drew, several hundred times a frame in busy areas. That work now goes to a thread on another core, and the game core moves on to the next object. In the Upper City and the Endar Spire fights each busy frame takes about a tenth less time, and motion feels smoother.

- **Setup mistakes show a message instead of a black screen.** A missing `kubridge`, `libshacccg`, `.so` file or `.obb` now opens a message box saying what is missing and where it goes.

- **16-bit textures could come out corrupted** when the game re-uploaded a texture, or updated one on a texture unit it had not just bound. Fixed.

- **Smaller fixes**: the missing-OBB message is shorter, and a few internal clean-ups in the loader's hooks and thread handling.

- **KOTOR-nolog.vpk**: an optional build with diagnostic logging disabled. Install it in place of `KOTOR.vpk` if you prefer not to have a log file written.

### Why only a tenth

The graphics library was not most of the frame. Most of a busy frame is the game's own code working out what is on screen and preparing each object, and that still runs on one core. PSVshell will still show that core at 100%: it is doing more frames in the same time, not less work. What this release moves off it is everything the port itself controls.

## Updating

Install `KOTOR.vpk` over your current one. Your files in `ux0:data/kotor/`, your saves and your mods stay as they are. If anything goes wrong, v0.4.3 is still on the releases page and installs the same way.

## Honest limits

- **Tested for one evening, not a playthrough.** Several sessions in the Taris Upper City and save loads, with no crashes and nothing wrong on screen. The rest of the game has not been played on this build yet, which is why it is a pre-release.

- **Mod sets have not been tried with this build.**

- **Busy areas still sit near 20 fps** with a crowd on screen; the remaining time is the game's own code.

- **The loading screen runs twice when you load a save** (issue #13). It fills once without a tip, then again quickly with one. It happens in v0.4.3 too, and the save loads normally.

- **The rare crash after an area-change auto-save** (issue #12) is still open.

## Everything else from v0.4.3 still applies

The 1.0.10, 1.0.9 build 54 and 1.0.7 / 1.0.71 APKs work, Griff spawns in the Sand People Enclave, texture quality is picked from the MODS button, busy areas have 96 sound channels, and frames are locked to 30 fps.

## You need your own copy of the game

This is a loader, not a game. It needs the Android release's `main` and `patch` `.obb` files, which you must own.

## Something broken?

Open an issue with `ux0:data/kotor/log.txt` attached, and say where in the game it happened.
